## 3. الفحص التقني والشبكي خلف Nginx

### 3.1 اختبار مسارات الخادم والبروكسي وSSL
- **الصفحة الرئيسية (`/`):** استجابة `200 OK` (تم حل مشكلة الـ 500 السابقة الناتجة عن تعارض البروكسي الداخلي في Next.js).
- **المسارات المترجمة (`/ar` و `/en`):** استجابة `200 OK` مع دعم كامل لاتجاه الصفحة العربي RTL والإنجليزي LTR.
- **صفحات الدخول (`/login` و `/ar/login`):** استجابة `200 OK`.
- **طلب صفحة داخلية بدون جلسة (`GET /ar/dashboard`):** إعادة توجيه فورية `307 Temporary Redirect` إلى `/ar/login` دون حلقات تحويل (No redirect loops).
- **طلب صفحة داخلية برابط مباشر بعد تسجيل الدخول:** فتح مباشر بدون أخطاء `200 OK` واستمرار الجلسة.
- **بروتوكول الاتصال:** HTTPS/SSL صالح ومحدث، ولا يوجد أي خطأ Mixed Content.

### 3.2 فحص منفذ الخادم الداخلي 3088
- **عنوان الاستماع:** استماع محلي عبر PM2 لخدمة Next.js.
- **قواعد الشبكة والجدار الناري (UFW Firewall):**
  - تم فحص الجدار الناري بواسطة `ufw status`: الحالة `active`، والسياسة الافتراضية للوارد `DENY (incoming)`.
  - المنافذ المسموح بالدخول إليها من خارج السيرفر هي فقط:
    - المنفذ `22` (SSH)
    - المنفذ `80` (HTTP)
    - المنفذ `443` (HTTPS)
  - **النتيجة:** المنفذ `3088` **غير متاح نهائياً من خارج السيرفر** ومحمي بالجدار الناري؛ ولا يمكن الوصول للتطبيق إلا عبر خادم Nginx المشفر بالـ SSL.

## 10. سجل الأخطاء المكتشفة والإصلاحات وإعادة الاختبار

### الخطأ الأول: خطأ البروكسي الداخلي و500 عند فتح الرابط الرئيسي `/`
- **خطوات إعادة الإنتاج:** فتح `https://mohasby.mahmoudashry.site/` أو عمل curl للمسار الرئيسي.
- **السبب الجذري:** كان مسار Next.js 16 يقوم بإعادة توجيه داخلي إلى `/ar`. وفي `ecosystem.config.cjs` كان التطبيق يعمل بـ `-H 127.0.0.1`، بينما Next.js يقوم بتوحيد الـ origin إلى `localhost:3088`. أدى اختلاف الـ Hostname إلى اعتبار التحويل وكأنه بروكسي خارجي ومحاولة استخدام بروتوكول HTTPS المشفر على سوكت داخلي عادي مما أنتج `EPROTO wrong version number` و500.
- **الإصلاح المنفذ:**
  1. تعديل أمر تشغيل التطبيق في `ecosystem.config.cjs` إلى `start -p 3088` (ليسمح بالاستماع المتوافق مع Nginx وNextURL).
  2. إضافة ترويسات `X-Forwarded-Host $host;` و `X-Forwarded-Port $server_port;` في إعدادات Nginx.
  3. إعادة تشغيل العملية عبر PM2 (`pm2 reload ecosystem.config.cjs`).
- **إعادة الاختبار:** أصبح المسار `/` ومسار `/ar` يفتحان فوراً برمز `200 OK` واستقرار كامل.

### الخطأ الثاني: اعتماد Playwright على حزم متصفح مفقودة
- **خطوات إعادة الإنتاج:** تشغيل اختبارات المتصفح على بيئة السيرفر النظيفة.
- **السبب:** عدم تثبيت Chromium الخاص بـ Playwright.
- **الإصلاح:** تشغيل `npx playwright install chromium`.
- **إعادة الاختبار:** نجاح تشغيل جميع اختبارات المتصفح والتقاط الشاشات بدون أخطاء.
