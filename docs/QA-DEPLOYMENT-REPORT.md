## 2. إجراءات الأمان وتدوير كلمات المرور وإلغاء الجلسات

1. **تدوير كلمات المرور للحسابات المنشورة سابقاً:**
   - تم تدوير كلمات المرور لكافة حسابات الاختبار السابقة (`qa-admin@example.test`، `qa-accountant@example.test`، `qa-auditor@example.test`) في قاعدة البيانات الحقيقية وتحديث تجزئة كلمات المرور `passwordHash` بقيم عشوائية آمنة ومشفرة عبر خوارزمية `scrypt`.
   - لم يتم نشر أو تضمين أي كلمة مرور في الكود أو المستودع أو مخرجات التقرير.
2. **إلغاء الجلسات السابقة فوراً (Session Revocation):**
   - تم حذف وإلغاء كافة الجلسات النشطة لحسابات QA من جدول الجلسات `Session` في PostgreSQL بالكامل.
   - تم التحقق من قاعدة البيانات: عدد الجلسات المتبقية يقتصر فقط على جلسة مدير النظام الأصلي.
3. **توليد كلمات المرور ديناميكياً في السكربتات:**
   - تم تعديل `scripts/setup-qa-company.ts` و `scripts/qa-acceptance-test.ts` لحذف أي كلمات مرور ثابتة (Hardcoded Passwords).
   - تستقبل السكربتات كلمة المرور حصراً من متغير البيئة `process.env.QA_PASSWORD` دون أي قيمة افتراضية ثابتة، أو تولد كلمة مرور تشفيرية عشوائية قوية لكل تشغيل عبر `crypto.randomBytes(24)` دون طباعتها.
4. **طبيعة الجلسات في النظام (تصحيح وتدقيق تقني):**
   - نظام إدارة الجلسات في «محاسبي» **لا يستخدم رموز JWT الموقعة**، بل يعتمد على **رموز عشوائية (Random Hex Tokens بطول 64 محرفاً)** تُحفظ كـ Hash مشفر عبر خوارزمية `SHA-256` داخل حقل `tokenHash` في جدول `Session` بقاعدة البيانات، ويتم إرسال الرمز الأصلي في كوكي `mohasby_session` محمي بخاصية `httpOnly` و`Secure`.
