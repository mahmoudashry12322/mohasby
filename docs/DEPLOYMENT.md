# تثبيت محاسبي

المشروع يحتوي الواجهة وواجهات API معاً. PostgreSQL خدمة مستقلة يتصل بها المشروع عبر `DATABASE_URL`. لا توجد خطوة لكتابة ربط يدوي بين الواجهة والباك إند.

## المتطلبات

- Node.js 22 LTS، وnpm.
- PostgreSQL 16 أو أحدث، وقاعدة ومستخدم مخصصان للتطبيق.
- HTTPS أمام التطبيق باستخدام Nginx أو reverse proxy مماثل.
- المنفذ الداخلي الافتراضي 3088.

## تثبيت جديد

```bash
npm ci
cp .env.example .env
chmod 600 .env
```

عدّل `.env`: بيانات PostgreSQL، عنوان الموقع الحقيقي في `APP_URL`، اسم الشركة، وبريد وكلمة مرور المدير. كلمة المرور لا تقل عن 12 حرفاً. لا ترفع هذا الملف إلى GitHub.

```bash
npm run db:generate
npm run db:migrate
npm run db:seed
npm run setup:admin
npm run build
pm2 start ecosystem.config.cjs
pm2 save
```

بعد إنشاء المدير، احذف قيمة `ADMIN_PASSWORD` من `.env`. أمر إنشاء المدير يرفض استبدال كلمة مرور مستخدم موجود. جلسات الإنتاج تتطلب HTTPS لأن cookie مؤمّنة.

دليل الحسابات الأولي لا يحتوي معاملات العميل أو أرصدته. راجع الدليل واضبط الحسابات الخاصة بالنشاط ثم أدخل الأرصدة الافتتاحية بقيد متزن.

## ترقية قاعدة الإصدار الأول

الإصدار الأول كان يحتوي `companies` و`accounts` فقط، وربما أنشئا باستخدام `prisma db push`. لا تشغّل baseline فوق جداول موجودة.

1. خذ نسخة قابلة للاستعادة من القاعدة قبل تغيير هيكلها.
2. قارن الهيكل الفعلي بملف `prisma/migrations/20261005000000_baseline/migration.sql`.
3. إذا كان الهيكل مطابقاً لهذا الـbaseline فقط، علّمه مطبقاً ثم طبّق الإضافات:

```bash
npx prisma migrate resolve --applied 20261005000000_baseline
npm run db:migrate
npm run db:generate
npm run setup:admin
npm run build
pm2 restart ecosystem.config.cjs --update-env
```

لا تستخدم `migrate reset` على قاعدة العميل. إذا كان الهيكل مختلفاً، جهّز migration مناسبة بعد المقارنة، ولا تعلّم baseline مطبقاً لمجرد تجاوز خطأ.

حقل `Account.balance` القديم لا يُستخدم كمصدر للأرصدة. لو كانت هناك أرصدة فعلية فيه، يجب نقلها إلى قيد افتتاحي متزن بعد مراجعة المدين والدائن. لا تضفها مرة أخرى إن كانت مُدخلة بالفعل كقيود.

## Nginx

داخل إعداد HTTPS للموقع، وجّه الطلبات إلى التطبيق:

```nginx
location / {
    proxy_pass http://127.0.0.1:3088;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    client_max_body_size 1m;
}
```

اضبط `APP_URL` ليطابق الـorigin العام تماماً. لا تعرض منفذ PostgreSQL للعامة.

## قبل إدخال معاملات العميل

1. سجل الدخول بحساب المدير.
2. اضبط اسم الشركة ودليل الحسابات والفترات المالية.
3. أضف العملاء والموردين والشركاء واربط كل سجل بحسابه التفصيلي.
4. أضف الأصناف والمخازن. لكل صنف: حساب المخزون، المشتريات، تغير المخزون، والمبيعات. حساب تغير المخزون يجب أن يكون حساب تكلفة ضمن قائمة الدخل.
5. أدخل الأرصدة الافتتاحية المالية والمخزنية. إدخال افتتاحي مخزون ينشئ قيده أيضاً؛ لا تكرر نفس قيمة المخزون في قيد افتتاحي آخر.
6. صنّف حسابات النقدية والبنوك ورأس المال العامل وغير النقدي من الإعدادات حتى تصبح تقارير التدفقات قابلة للمطابقة.
7. نفّذ شراءً وصرفاً ومرتجعاً وجرداً في بيئة اختبار، ثم طابق النتائج قبل الاستخدام الفعلي.

## التشغيل المحاسبي

- القيود اليدوية تحفظ مسودة ثم تُرحّل. المسودة لا تؤثر على التقارير.
- المستندات التجارية تحفظ حركة المخزون والقيد في transaction واحدة.
- الصرف لا ينشئ مصروف تكلفة قبل إقفال المخزون؛ الطريقة المختارة متوسط الفترة المرجح.
- إقفال الفترة يقيّم المخزون ويرحّل الفرق بين قيمة المخزون المحسوبة ورصيده الدفتري إلى حساب تغير المخزون، ثم يقفل كل التواريخ حتى نهاية الفترة.
- لا يعاد فتح إقفال المخزون النهائي من الواجهة. التصحيحات تتم في فترة مفتوحة، مع الاحتفاظ بسجل المراجعة.
- الإهلاك شهري على أساس نهاية الشهر، بحد القيمة المتبقية، وبأقصى 12 شهراً في عملية واحدة. شهر الشراء محسوب كشهر كامل؛ راجع هذه السياسة مع العميل.

## التحقق

```bash
npm run typecheck
npm test
npm run test:integration
npm run build
npx playwright install chromium
npm run test:http
```

الاختبار المحلي يستخدم PGlite (PostgreSQL إلى WebAssembly) مع بيانات صناعية، ولا يقرأ قاعدة العميل. اختبار المتصفح ينشئ خادماً محلياً مؤقتاً. Workflow GitHub المرفق يشغّل اختبار PostgreSQL 16 والتزامن؛ راجع نتيجته، ثم تحقق من التشغيل والنسخ الاحتياطية على بيئة التسليم قبل الاعتماد النهائي.

## حدود النطاق

لم تُنقل معاملات ملف Excel أو أسماء عملائه أو أرصدته إلى المستودع العام. سكربت `scripts/audit-workbook.py` يستخرج خريطة خاصة للمراجعة، ولا يستورد البيانات تلقائياً إلى الإنتاج. الرواتب والاشتراكات ومحفظة الشيكات لم تكن ضمن الملف المرجعي، وأزيلت روابطها التجريبية من القوائم.

التقارير المحاسبية تعمل بالعملة الأساسية للشركة. لا يوجد دفتر أستاذ متعدد العملات أو إعادة تقييم فروق عملة آلية. سعر الصرف في تقارير تكلفة الاستيراد والتصدير مدخل صريح للتقرير.
