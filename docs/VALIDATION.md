# التحقق وقبول التسليم

## الاختبارات الآلية

- `npm test`: 12 اختبارًا وحدات تشمل الوزن وخصوماته، توازن Decimal، تكلفة الاستيراد، الإهلاك، تحليل صيغ التكلفة الـ254، تكلفة التصنيع، تجميع SUMIFS، القسمة على صفر، ونسب الشركاء وتقريب القروش، وحصر 43 زرًا، وحسابات المرتبات و79 صيغة توزيع جديدة.
- `npm run test:integration`: تطبيق migrations الثلاثة على قاعدة اختبار ثم الترحيل والعكس وعدم التكرار وعزل الشركات، المتوسط الدوري ورفض السالب والإقفال وحمل الرصيد للفترة التالية، وتكلفة زراعية من القيود دون تكرار المدين والدائن.
- عند تعيين `TEST_DATABASE_URL` يستخدم اختبار التكامل قاعدة PostgreSQL **اختبارية فارغة بعد migrations** ويضيف اختبارات تزامن: إعادة نفس الطلب، ترقيم ثمانية قيود متزامنة، وصرفين يتنافسان على نفس الرصيد. لا توجه هذا المتغير إلى قاعدة عميل.
- `npm run test:http`: خادم production محلي مع PGlite مؤقت، جلسات وصلاحيات ورفض CSRF، مستند شراء مرتبط بالمخزون والقيد والتكلفة، واختبارات المرتبات والسلف والترحيل وتثبيت الراتب ومنع تعديل الشهر المرحل وعزل السنوات، وحفظ توزيع الشريكين، ثم Chromium يراجع أزرار Home الـ43 ومواضعها، ويحفظ ويرحّل قيداً من الواجهة ويفتح مسارات الداشبورد ويصور عرض الجوال.
- `npm run typecheck` و`npm run build`: صحة الأنواع وبناء الإنتاج. `npm run lint`: فحص Next.js مع تحذيرات أداء React المتعلقة بالواجهات الموروثة.
- `npm audit --omit=dev`: فحص الاعتماديات المنشورة. النتيجة صفر في 2026-10-05 بعد تحديث Next.js/React/next-intl/sharp وتثبيت deepmerge-ts/postcss؛ النتيجة مؤرخة وليست ضماناً دائماً.

PGlite يستخدم اتصالاً واحداً؛ نجاحه لا يثبت التزامن على PostgreSQL الحقيقي. Workflow المرفق يشغّل PostgreSQL 16 مستقلاً ويطبق migrations ويختبر التزامن. نجاح فحص parsing لكل صيغة لا يعني مقارنة جميع أرصدة العميل السابقة؛ اختبارات الأرقام تستخدم بيانات صناعية معلومة النتائج.

صور المتصفح الناتجة تحفظ في `test-results/` وتستبعد من git. يمكنك تمرير `CHROMIUM_PATH` لتشغيل نسخة Chromium مثبتة؛ الافتراضي تثبيت Playwright.

## قبول نسخة العميل

1. تثبيت قاعدة منفصلة وتشغيل migrations وseed وإنشاء المدير، ثم تسجيل الدخول عبر HTTPS.
2. مطابقة افتتاحي المدين والدائن مع ميزان معتمد؛ لا تكرر قيد افتتاحي المخزون الذي ينشئه إذن الافتتاحي.
3. اختيار معاملات شراء وبيع ومرتجع وخصومات وزن وهالك من الملف، إدخالها، ومقارنة كمية المخزون والقيمة والدفتر والأستاذ.
4. مطابقة تقرير واحد من كل نشاط تكلفة، وضبط أسماء البنود وتصنيف الأصناف ومراكزها ومدخلات الفترة.
5. اعتماد اختلافات المصدر الموضحة في WORKBOOK-MAPPING، ونسب الشركاء، وسياسة الإهلاك ومجموعات الدخل وتصنيفات التدفق النقدي.
6. إقفال فترة اختبار ومراجعة قيد فرق المخزون والأرصدة المرحلة للفترة التالية؛ الإقفال نهائي في واجهة التطبيق.
7. اختبار مستخدم محاسب ومراجع ومدير، وإيقاف حساب وتغيير كلمة مروره، والتأكد من بطلان جلساته.
8. تجربة استعادة نسخة PostgreSQL احتياطية في بيئة مستقلة قبل تسليم بيانات حقيقية.

## حدود النسخة

- الواجهة التشغيلية الجديدة عربية؛ هيكل الموقع القديم يدعم تبديل اللغة، لكن حقول الشاشات الجديدة لم تترجم كلها إلى الإنجليزية.
- جداول الشركاء تحليلية ولا ترحّل قيد توزيع تلقائياً. فائدة/راتب الشريك والتمويل مدخلات فترة، والرصيد الدفتري يظهر للمقارنة.
- بيانات المصنف الأصلية لم تُستورد، ولا يوجد مستورد معاملات تاريخية جاهز؛ أداة تدقيق المصنف للقراءة فقط.
- لا توجد إدارة اشتراكات أو حضور وانصراف يومي أو شيكات مؤجلة أو فاتورة إلكترونية ضريبية أو دفتر عملات متعددة.
- التقارير والكشوف قابلة للطباعة وCSV؛ نموذج فاتورة ضريبية مطابق لهيئة محددة ليس ضمن هذه النسخة.
- كشف المستندات يعرض أحدث 100 مستند؛ التقارير المالية ودفاتر الأستاذ تستخدم الفترة المختارة. القيود تعرض 50 في الصفحة.

هذه معايير اعتماد التشغيل الفعلي؛ رفع الكود وبناؤه لا يعادل اعتماد أرصدة العميل أو نشره على السيرفر.
